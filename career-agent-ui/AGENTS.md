# Career Agent UI - Development Rules

These rules apply to ALL code changes in the frontend. Follow them in every session without exception.

## Next.js 16 / React 19 Rules

1. **App Router only.** All routes use the `app/` directory with file-system routing. No Pages Router (`pages/`).

2. **Components are Server Components by default.** Only add `"use client"` when the component needs state, event handlers, browser APIs, or hooks (useState, useEffect, useRouter, etc.). Keep as much UI as possible on the server.

3. **Use `"use client"` at the narrowest boundary.** Don't mark an entire page as client - extract the interactive part into a small Client Component and keep the parent as a Server Component.

4. **Use `PageProps` and `LayoutProps` type helpers** (globally available in Next.js 16) instead of manually typing params/searchParams. They are generated by `next dev` / `next build` / `next typegen`.

5. **Dynamic route params are async.** In Next.js 16, `params` is a `Promise`. Use `const { id } = await params` in Server Components, or `useParams()` in Client Components.

6. **Use `<Link>` from `next/link`** for all internal navigation. It provides prefetching and client-side navigation by default. Set `prefetch={false}` only for routes that don't exist yet.

7. **Use `loading.tsx`** files for route-level loading states. Use `<Suspense>` with meaningful fallbacks for more granular streaming within a page.

8. **Use `error.tsx`** files for route-level error boundaries. Error boundaries must be Client Components (`"use client"`). Use `retry()` (not `reset()`) in Next.js 16 error boundaries.

9. **Use `not-found.tsx`** files and the `notFound()` function from `next/navigation` for 404 states.

10. **Route Handlers** (`route.ts`) go in the `app/api/` directory. Use standard Web APIs (Request, Response) - not Next.js-specific helpers.

11. **Environment variables** prefixed with `NEXT_PUBLIC_` are exposed to the client. All other env vars are server-only. Never access non-prefixed env vars in Client Components.

## UI Framework Rules

12. **Use Material UI (MUI) v9** for all components. No Tailwind CSS, no shadcn/ui, no custom CSS classes.

13. **Use tree-shaking imports:** `import Button from "@mui/material/Button"` - NOT `import { Button } from "@mui/material"`.

14. **Use the `sx` prop** for all styling. No `className` with utility classes. No inline `style` objects.

15. **Use `@mui/icons-material`** for all icons with tree-shaking imports. No lucide-react, no heroicons.

16. **Use `AppRouterCacheProvider`** from `@mui/material-nextjs` in the root providers for SSR/streaming compatibility with App Router.

## State Management Rules

17. **Zustand** for client-only state (auth token, UI preferences). Stores live in `src/store/`. Keep stores small and focused - one store per concern.

18. **React Query (`@tanstack/react-query`)** for all server state (API data fetching, mutations). Never use raw `useEffect` + `fetch` for API calls in Client Components.

19. **Custom hooks** for API operations go in `src/hooks/`. Each hook wraps `useQuery` or `useMutation` with proper typing.

20. **Invalidate related queries** after successful mutations via `queryClient.invalidateQueries()` to keep the UI in sync. Invalidate by query key prefix, not individual keys.

## API Rules

21. **Use the Axios instance** from `src/lib/api.ts` for ALL API calls. Never create additional Axios instances or use raw `fetch` for backend calls.

22. **JWT token** is attached automatically by the Axios request interceptor. Never manually set `Authorization` headers.

23. **401 responses** trigger automatic logout and redirect to `/login` via the Axios response interceptor. No manual 401 handling needed in components.

## TypeScript Rules

24. **Strict TypeScript** - no `any` types, no `@ts-ignore`. Define interfaces for all API request/response shapes in `src/types/`.

25. **Use `interface`** for object shapes (API responses, component props). Use `type` only for unions, intersections, and utility types.

26. **Use Zod** for runtime validation of API responses where data integrity is critical (e.g., parsing untrusted external data).

## Component Rules

27. **Show loading states** using MUI `Skeleton` for content areas and `CircularProgress` for action buttons. Use `loading.tsx` for route-level loading.

28. **Show errors** using MUI `Alert` for persistent errors and `Snackbar` for transient feedback (success/error after mutations).

29. **Use MUI form components consistently:** `TextField` for text inputs, `Select` for dropdowns, `Autocomplete` with `freeSolo` and `disableCloseOnSelect` for multi-value tag inputs with checkbox indicators.

30. **Use `date-fns`** for all date formatting. Never use raw `Date.toLocaleDateString()` or `Intl.DateTimeFormat` directly.

31. **Accessibility:** All interactive elements must have proper `aria-label` or visible label text. Use semantic HTML elements. MUI components provide accessibility by default - don't override it.

## File Structure

```
src/
├── app/                    # Next.js App Router (file-system routing)
│   ├── (auth)/             # Public routes (login, register) - route group
│   ├── (dashboard)/        # Protected routes with sidebar - route group
│   │   ├── layout.tsx      # Authenticated layout with navigation
│   │   ├── jobs/           # Jobs list and detail pages
│   │   ├── applications/   # Application tracking pages
│   │   ├── profile/        # Profile management
│   │   ├── workflows/      # Workflow history
│   │   └── settings/       # App settings
│   ├── api/                # Route Handlers (health check, etc.)
│   ├── layout.tsx          # Root layout (html, body, providers)
│   └── page.tsx            # Landing page
├── components/             # Reusable MUI components (shared across routes)
├── hooks/                  # Custom React Query hooks (useJobs, useProfile, etc.)
├── lib/                    # API client (api.ts), theme config, providers
├── store/                  # Zustand stores (authStore, etc.)
└── types/                  # TypeScript interfaces (job.ts, profile.ts, etc.)
```

## Package Manager

32. **Use `pnpm`** for all package operations. Never use npm or yarn.

## Testing Rules

33. **Vitest** for unit tests. **fast-check** for property-based tests.

34. **React Testing Library** for component tests. Test user behavior and accessibility, not implementation details.

## Build & Verification Rules

35. **Run `pnpm build`** after every code change to verify TypeScript compilation and Next.js build passes before claiming completion.

36. **No build warnings allowed.** Fix TypeScript errors, unused imports, and missing dependencies before committing.

## Git Rules

37. **Provide a GitHub commit message** at the end of every session summarizing all frontend changes.

38. **Never commit secrets** or real API keys. Use `.env.local` (gitignored) for local development values.
